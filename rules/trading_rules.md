# 交易执行规则

## 合约标准化规则

CTP 各交易所合约代码大小写规则不同，必须统一标准化后使用：

| 交易所 | 大小写规则 | 示例 |
|--------|-----------|------|
| SHFE（上期所） | 小写产品代码 | `zn2606`, `au2606` |
| DCE（大商所） | 小写产品代码 | `m2609`, `i2609` |
| GFEX（广期所） | 小写产品代码 | `si2606` |
| CFFEX（中金所） | 大写产品代码 | `IC2606`, `IF2606` |
| CZCE（郑商所） | 大写产品代码，3位年月 | `SA405`, `CF609` |

### CZCE 特殊处理
- 4位年月必须转换为3位：`SA2405` → `SA405`
- 正则匹配：`^([A-Z]{1,3})(\d{2})(\d{2})$`，替换为 `{product}{year_last_digit}{month}`
- 优先从 `instruments.json` 恢复精确大小写

## 报单防重复规则

### 四道防线
1. **Signal ID 去重**：`_processed_signal_ids` 持久化到 `.processed_ids.json`，相同报单编号跳过
2. **撤旧挂新**：`_get_pending_order_refs` 检查同合约+方向+开平的未成交委托，先撤单再重挂
3. **持仓检查**：平仓单报单前查询实际持仓，手数超过持仓量时自动调整或跳过
4. **1009 撤单重试**：平仓被拒绝（ErrorID=1009）时，立即撤掉该合约所有未成交平仓委托，下次持仓同步时重新计算差额后重试，不再干等冷却

### 执行顺序
```
待执行委托
  → Signal ID 去重
  → 字段解析与校验
  → 平仓单：持仓检查（手数超过持仓则调整或跳过）
  → 价格计算（文件价 / 市场价）
  → 撤旧挂新（同合约方向有 pending 则先撤）
  → 报单
  → 成功则保存 processed ids
```

## 价格规则

### 委托价格来源
| 环境 | 价格来源 | 说明 |
|------|---------|------|
| `online` | `signal.json` 中的价格 | 严格使用委托文件价格 |
| `simu` | `signal.json` 中的价格 | 严格使用委托文件价格 |
| `7x24` / `simu-vip` | 市场对手价 | 查询 `BidPrice1` / `AskPrice1` |

### 对价计算
- 买开/买平 → `AskPrice1`（卖一价）
- 卖开/卖平 → `BidPrice1`（买一价）
- 对手价为 0 时回退到 `LastPrice`

## 开平标志规则

| 方向 | 默认开平 | 说明 |
|------|---------|------|
| 买（Buy） | 开仓（Open） | 默认买开 |
| 卖（Sell） | 平仓（Close） | 默认卖平 |

### 上期所/能源中心特殊处理
- 有今仓时先平今（`CloseToday`），剩余再平昨（`CloseYesterday`）
- 其他交易所直接使用 `Close`

## 自动撤单重挂规则

### 触发条件
- 仅针对 **开仓委托**（平仓委托不自动重挂，避免持仓不足风险）
- 订单状态为 **未成交**（`THOST_FTDC_OST_NoTradeQueueing`）
- 从提交时间起超过 **60 秒** 仍未成交

### 执行流程
1. 后台监控线程每 **10 秒** 扫描一次 `_orders`
2. 超时开仓委托 → 发送撤单请求
3. 撤单后等待 0.5 秒，确认原单未成交
4. 查询最新行情对手价（`BidPrice1` / `AskPrice1`）
5. 用新价格重新提交限价开仓单
6. 最多重挂 **2 次**（原始订单 + 2 次重挂 = 最多 3 次下单）

### 限制
- 不处理已部分成交的订单（只处理完全未成交）
- 重挂次数达到上限后停止，等待人工干预
- 每次重挂发送飞书通知

## 持仓同步规则

### 触发时机
- `run_pipeline.py` 启动时执行一次完整同步
- 之后每 30 分钟执行一次（由 `_last_full_sync_time` 控制）
- 非交易时段也执行（`_do_sync` 线程每 30 秒检查）

### 同步逻辑
1. 解析 `hold-std.json` 得到目标持仓
2. 查询 CTP 实际持仓
3. 缺额：目标 > 实际 → 限价开仓
4. 超额：实际 > 目标 → 限价平仓
5. 平仓前双重检查：
   - 实际持仓 > 0（CTP 数据滞后保护）
   - 30 分钟全量冷却期内不重复操作同一合约（空仓需建仓除外）

## 交易时段

### 配置时段（`TRADING_SESSIONS`）
```python
[
    ("09:00:15", "11:30:00"),   # 日盘上午
    ("13:30:15", "15:15:00"),   # 日盘下午
    ("21:00:15", "23:59:00"),   # 夜盘
    ("00:00:15", "02:30:00"),   # 凌晨夜盘
]
```

### 环境差异
- `online`：严格在交易时段内执行，日盘收盘后自动退出
- `simu` / `7x24`：跳过时段检查，持续运行

## 错误处理

| ErrorID | 含义 | 处理策略 |
|---------|------|---------|
| 1006 | 合约不存在 | 记录到 `_invalid_instruments`，后续跳过 |
| 1009 | 持仓不足 | 撤掉该合约所有未成交平仓委托，下次重新计算后重试 |
| 其他 | 视情况 | 打印日志并通知飞书 |

## 并发模型

### 主线程（`run_pipeline.py`）
- 导出 CSV
- 委托对比
- 生成 `hold-std.json`

### 后台线程 `_do_sync`
- 持仓对齐（`sync_and_trade`）
- 内部有 30 分钟冷却，不阻塞主线程

### 后台线程 `_do_execute`
- 委托执行（`execute_orders`）
- 快速检查 `signal.json`，执行后清空

### 共享实例 `_mgr_holder`
- `PositionSyncManager` 单例，线程锁保护创建/销毁
- 两个后台线程共享同一个 CTP 连接
